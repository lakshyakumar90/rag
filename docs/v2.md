# RAG Workspace after v1 — Phase 1–3 + stretch foundations

This document is the operational companion to the implementation. v1 data is
preserved: every migration is additive, PostgreSQL remains the source of truth,
and pgvector remains a fallback until reads are switched to Qdrant.

## Phases shipped

### Phase 1 — Qdrant vector search

- `docker-compose.yml` and `docker-compose.prod.yml` add a pinned
  `qdrant/qdrant:v1.12.1` service with a persistent `qdrant_data` volume, a
  loopback-only dev port and an HTTP `/healthz` readiness check. No public port
  is exposed in production; the API and worker use the Compose network.
- `apps/api/providers/qdrant.py` is a small `httpx` REST client (no new Python
  dependency). Point IDs are the PostgreSQL chunk UUIDs, so writes are
  idempotent. Payloads carry `workspace_id`, `document_id`,
  `embedding_profile`, `index_version`, `chunk_index` and `page_number` — never
  chunk text.
- `apps/api/services/qdrant_index.py` replaces a document's points atomically
  (delete-then-upsert), records a checkpoint in `qdrant_sync_state`, and is used
  by the worker, document delete/re-index and the backfill script.
- `RetrievalService` queries Qdrant with workspace/profile/document filters,
  then `RetrievalRepository.verify_qdrant_hits` re-checks every hit in
  PostgreSQL (workspace, `ready` status, profile, index version, grants) before
  returning text or building citations. PostgreSQL `tsvector` keyword search is
  unchanged; results are fused by the existing RRF pipeline.
- `QDRANT_FALLBACK_TO_PGVECTOR=true` (default) keeps reads working if Qdrant is
  down; set it to `false` to fail closed with `503 VECTOR_INDEX_UNAVAILABLE`.

**Backfill, switch and rollback** (from the repo root):

```bash
uv run python scripts/backfill_qdrant.py --dry-run    # see what would be copied
uv run python scripts/backfill_qdrant.py              # resumable; safe to rerun
uv run python scripts/backfill_qdrant.py --verify     # counts + sample searches
# only then: QDRANT_ENABLED=true (and QDRANT_FALLBACK_TO_PGVECTOR=false if desired)
# rollback: QDRANT_ENABLED=false
# full rollback: uv run python scripts/backfill_qdrant.py --rollback
```

Only documents whose `embedding_model`, `embedding_dim` and profile match are
copied; incompatible profiles are never re-embedded into the same collection.

### Phase 2 — Honest indexing progress

Progress is stored on `documents` and committed by the worker phase by phase:
`uploading → queued → reading → ocr → chunking → embedding → indexing → ready`.
Fields include page/section totals, chunks created/embedded/indexed, OCR page
counts, `progress_updated_at`, `index_version` and `qdrant_synced_at`.

Weighted phases (documented in `apps/api/core/progress.py`) are
`uploading 5, queued 2, reading 15, ocr 8, chunking 10, embedding 35, indexing 25`.
The OCR weight is skipped when there is no OCR work, and the remaining weights
are normalised. A document is **100% only when `status == ready`**; an unknown
total produces `progress_percent = null` and an indeterminate bar with an
explanatory text label. Upload progress is tracked separately by the browser
(XHR) and is never mixed with indexing progress.

The Documents page shows phase, factual detail ("Reading page 12 of 40",
"Embedded 120 of 300 chunks", "Confirmed 40 of 300 chunks in the search index"),
accessible `role="progressbar"` text, and a retry action for failed documents.
Polling continues while pending/processing and survives reloads.

### Phase 3 — Settings tests and the Chat composer

- `GET /api/v1/ai/providers` lists built-ins (Ollama, OpenAI,
  OpenAI-compatible, Anthropic, Codex/OpenCode/Claude CLI) plus the user's
  encrypted BYOK configs, with availability and discovery flags.
- `POST /api/v1/ai/test` runs a one-token request with the **selected model**
  and classifies failures as `authentication`, `unsupported_model`, `quota`,
  `timeout`, `unavailable` or `invalid_request`. Secrets are replaced with
  `***` in errors and never appear in responses or logs.
- `GET /api/v1/ai/models` discovers models from Ollama `/api/tags`, OpenAI
  `/models`, Anthropic `/models` or local CLIs; manual model ids are always
  allowed.
- `GET/PUT /api/v1/ai/defaults` persists per-user provider/model defaults. No
  existing default is changed until the user saves.
- The Chat composer now owns provider + model selectors, the multiline input
  and Send/Stop/Regenerate. Enter sends, Shift+Enter inserts a newline. New
  chats use Settings defaults; changing the selector PATCHes the conversation
  (`PATCH /workspaces/{id}/conversations/{id}/selection`) so the choice survives
  reloads. Answers record and display the provider/model that actually
  generated them. The transcript scrolls independently and only auto-scrolls
  when the reader is already at the bottom ("Jump to latest" appears otherwise).
- Ctrl/Cmd+K opens **one** workspace search panel with page navigation and
  document results; selecting a result pre-fills the chat composer.

### Stretch goals shipped

- **Per-document permissions.** Existing documents are unrestricted and keep
  the workspace-role default. Setting `restricted=true` switches to an explicit
  grant allow-list. `DocumentAccessService` is applied to search, chat context,
  citation construction, document listing, metadata and download URLs; Qdrant
  hits are re-verified in PostgreSQL. Managing grants requires owner/admin.
- **Exact query caching.** `query_cache_entries` keys include workspace,
  normalised query, retrieval settings, embedding profile and document filter;
  the authorization scope is the caller's role plus visible document ids. A
  cache hit re-checks cached citations against current access. Entries expire
  after five minutes and are invalidated on upload, re-index, delete, OCR/index
  completion and grant changes. `GET /api/v1/ai/cache-stats` reports hits,
  misses, hit rate and lookup latency.
- **Embedding profiles (foundation).** `embedding_profiles` stores provider,
  model, dimension, distance, version, enabled state and validation time, with
  the shipped Ollama profile seeded as enabled. Collection names are derived
  from the profile id, so profiles sharing a dimension but using different
  models never share a collection.

## Live stack check

The dev Compose stack was started with alternate host ports because this host
already owns `11434` (Ollama) and `8000`:

```bash
API_PORT=18000 OLLAMA_PORT=11435 docker compose up -d
```

All services reached `healthy`/`Up`; `alembic upgrade head` exited 0. The demo
workspace (3 pre-v1 documents plus a 6-page PDF) was backfilled with
`scripts/backfill_qdrant.py --force` and `--verify` reported counts and sample
retrieval matches. After `QDRANT_ENABLED=true`, a search returned the expected
`support.txt` citation for the VPN question, and Qdrant's `/metrics` confirmed
21 successful `POST /collections/{name}/points/query` calls from the API. A
re-index of the 6-page document was polled live and showed
`reading 0/6 → embedding 6/6 pages → ready 6/6 chunks indexed, 100%`.

Fixes made during that check: the pinned Qdrant image has no `curl`, so its
healthcheck uses bash `/dev/tcp`; dev `x-api-env` now sets
`OLLAMA_BASE_URL=http://ollama:11434`; the document list repository selects the
full entity so progress/profile fields reach the UI; the backfill ignores the
read-path `QDRANT_ENABLED` flag and fails loudly on partial writes; Ollama
model tests pass `model` per call (its constructor has no `model` argument) and
classify a missing model as `unsupported_model`.

## Stretch goals shipped

| Goal | Implementation |
|---|---|
| Agent mode | `POST /workspaces/{id}/agent` runs a bounded loop (max 4 steps, 30s deadline, cancellable) over four read-only typed tools: `document_search`, `web_search`, `calculator` (constrained `ast` evaluator), `summarize_document`. Tools re-check workspace/document grants; output is sanitized and labelled untrusted. SSE `tool_start`/`tool_result`/`done` frames render activity and distinguish web from workspace citations. |
| OCR for scanned PDFs | API image installs Tesseract + English data. `extract_pdf` detects low-text pages, OCRs only those, preserves page numbers/order, reports per-page progress, flags `unreadable_pages`, and keeps those pages searchable with a marker. `POST /documents/{id}/ocr-retry` re-runs ingestion without a fresh upload. Tests cover text-only, scanned, mixed and corrupt PDFs. |
| Bring-your-own embeddings | Profile CRUD + real sample validation (`POST /embedding-profiles/{name}/validate`), encrypted keys, separate Qdrant collections per profile id, and `POST /embedding-profiles/workspaces/{id}/switch`: an ARQ job builds the replacement index for every ready document, then flips `workspaces.active_embedding_profile` only after all points exist. Ingestion and query embeddings follow the active profile. |
| Sources beyond uploads | `POST /workspaces/{id}/sources` imports URLs and GitHub repos through the same worker, with DNS-level private-address blocking, redirect rejection and size caps. Notion export ZIPs use the bounded upload parser. Canonical URL / repository+commit / page titles are preserved in `source_metadata`. |
| Multilingual support | Distinct `multilingual-embeddinggemma-768-v1` profile; Unicode-preserving chunking and original citation text; `evals/multilingual.py` probes same-language and cross-language recall@3. |
| Semantic query caching | Opt-in (`SEMANTIC_CACHE_ENABLED`) with cosine threshold `SEMANTIC_CACHE_THRESHOLD=0.92`. Hits require the same workspace, authorization scope, TTL and embedding profile; cached citations are re-checked against current access. Exact caching remains the default. |

## Local environment notes

- The checked-in `.env` sets `REFRESH_COOKIE_SECURE=false` and
  `ENABLE_CLI_PROVIDERS=true`. Four v1 tests assume the default values; run
  them with `REFRESH_COOKIE_SECURE=true ENABLE_CLI_PROVIDERS=false` or use
  `.env.example`.
- On this Windows host a previous `.next/standalone` directory is locked, so
  the normal `pnpm build` can report `EBUSY`. The production build was verified
  using a clean output directory; no source change is required.
- `pnpm api:types` runs `scripts/pin-openapi-typescript-peer.mjs`, which points
  openapi-typescript's TS peer at the TS 5.9.3 copy already in the pnpm store;
  openapi-typescript 7 cannot use the app's TS 7 factory API.
